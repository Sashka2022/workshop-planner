# שיבוץ סדנאות · 3 סבבים

אפליקציית React + TypeScript לשיבוץ 9 מנחים ל־3 סבבי סדנאות. כל מנחה מדרג את 6 הסדנאות מהכי רוצים עד הכי פחות,
והאלגוריתם בונה שלושה סבבים מאוזנים: בכל סבב 3 סדנאות, בכל סדנה 3 מנחים, וכל מנחה מקבל 3 סדנאות שונות.

הסדנאות מוגדרות ב־`src/workshops.ts`.

## הרצה מקומית

```bash
npm install
cp .env.example .env   # ולמלא את הערכים
npm run dev
npm test               # בדיקות לאלגוריתם השיבוץ
```

בלי הגדרת Supabase האפליקציה עובדת, אבל הנתונים נשמרים רק בדפדפן הנוכחי.

## הגדרת שמירה משותפת (Supabase, חינם)

1. יוצרים פרויקט ב־https://supabase.com.
2. ב־SQL Editor מריצים את `supabase/schema.sql`.
3. ב־Project Settings → API מעתיקים את `Project URL` ואת מפתח `anon public`.
4. מכניסים אותם ל־`.env` כ־`VITE_SUPABASE_URL` ו־`VITE_SUPABASE_ANON_KEY`.
5. אופציונלי: `VITE_ADMIN_PIN` הוא קוד למארגן/ת. בלי קוד, כל אחד יכול לבנות שיבוץ.

הקוד הוא הגנה קלה בצד הלקוח, מתאימה לקבוצה קטנה ומהימנה. הוא לא מחליף הרשאות אמיתיות בשרת.

## פריסה ב־Vercel

1. מייבאים את הריפו ב־Vercel (Framework: Vite).
2. מוסיפים ב־Settings → Environment Variables את שלושת המשתנים מ־`.env.example`.
3. Deploy, ושולחים למנחים את הקישור.

## איך האלגוריתם עובד

Simulated annealing על מבנה שמבטיח מראש 3 סדנאות שונות בכל סבב ו־3 מנחים בכל סדנה. קנסות כבדים על מנחה שחוזר
לאותה סדנה ועל סדנה שרצה יותר מ־N סבבים (ברירת מחדל 2). העלות של כל שיבוץ היא ריבוע הדירוג, כך שהאלגוריתם מעדיף
שאף מנחה לא יקבל רק בחירות נמוכות. 30 הרצות אקראיות, והטובה ביותר נשמרת.
